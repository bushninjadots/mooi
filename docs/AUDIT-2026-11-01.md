# mooi — full audit, second pass

Date: 2026-11-01 · Pleamar 0.4.6 (language 0.4) · Lua 5.4 for the logic and the probe harness
Scope: the whole shell — `bin/mooi`, every scene (`shell/*.plm`, `shell/ui`, `shell/theme`,
`shell/player`, `shell/bmo`), every logic file (`shell/*.luau`, `shell/lib`, `shell/player`,
`shell/bmo`), the test suites, and every claim the documents make about them.
Predecessor: [AUDIT-2026-10-31.md](AUDIT-2026-10-31.md) (F1–F12). This pass checks what changed,
hunts for new defects with probes rather than eyes, and leaves a record of what it could not check.

## Method

1. `bin/mooi check` on HEAD: nine scenes compile, every logic file parses, BMO 27 tests, unit
   **285 tests — 0 failed**, exit status 0.
2. **Hostile-input probes** over the pure modules (34 calls per kind): empty/NUL/comment-shell
   strings, `-name`, `$(id)`, 4 000-character queries, 400-digit numbers, `1e999`, `0/0`, `2^1024`,
   17 open parentheses, a Hyprland-address injection, malformed store documents, `nil`/`NaN`/`inf`
   numbers, a nil settings document, every setter code from 0 to 700.
3. **Cross-checks of the wiring** (scene events, facts, texts, models against the logic) — see A8
   for why the naive version of this is not trustworthy, and A6 for the defect it did find.
4. **Documentation against the tree**: counts, table rows, version claims, decision numbering.
5. Read of the launcher's critical sections (`theme_sync`, `theme_watch`, `apps_sync`,
   `settings_link`, `snapshot`, `pace`) against the previous audit's fixes.

Nothing here is based on a live run of the shell: starting mooi would have drawn over the session,
and the behavioural suites would have taken the keyboard and pointer. That limit is stated again at
the end, and no claim below depends on a live observation.

## Verdict

The previous audit's headline defect — a gate that could not fail — is **fixed and stayed fixed**:
`check` now exits non-zero on a failing suite (watched fail, then pass, today), and its launcher
hardening survived (`theme_sync` releases its lock, `pace` no longer needs `bc`). The pure logic
held up under every hostile input the probe could throw at it: no wrong path, no wrong value, no
crash on anything a user can type or a file can hold.

What this pass found instead is **small and real**: four nil-argument assumptions in code called
with a "not yet" value, one whole-section settings failure that was silently swallowed, one visible
button wired to nothing, and three top-level documents that had drifted from the tree. All but the
button were fixed with tests; the button is fixed too. The remaining structural debt is unchanged
and is the same as last time: no CI, no shellcheck on this machine, the bar scene is a monolith,
and there is no fresh performance or live-UI evidence.

## Findings

Severity: **High** = wrong behaviour a user can hit; **Medium** = wrong behaviour in a narrower
case, or evidence that cannot be trusted; **Low** = hygiene or robustness.

### A1 · Medium · A whole settings group of the wrong type vanished without a word — fixed

`lib/config.validate` walked the schema leaf by leaf, so a wrong **leaf** was reported with path,
reason and default, while a wrong **section** never reached a leaf: `{ atlas = "nope" }` produced
**0 problems** and every atlas setting silently fell back to its default. Reproduced in the probe
(`string where table -> ok, problems=0`). This is exactly the shape a hand edit or a truncated write
leaves behind.

Fixed in `shell/lib/config.luau`: every known section is now checked before the leaves, and a
non-table group is reported as `<path>: expected a group of settings, got <type>; using the
defaults`. Test: `a whole section of the wrong type is reported, not silently reset` (one problem,
the message names the group, defaults still used, a right group stays quiet).

### A2 · Low · Two "choice transports" had no schema default — fixed

`bar.edge` and `frame.motion` are settings the settings window writes to express a choice; choosing
one writes `bar.frame` + `bar.outline_width` (or `frame.music` + `frame.style`), and the window
derives the choice back with `style.edge_index` / `motion_index`. Neither row had a `default`, so
`config.defaults()` left them `nil` (the round-trip probe reported "cannot round-trip"), and a file
carrying one kept a value nothing reads for behaviour.

Fixed: both get the neutral default (`"none"`, `"off"`) and a comment saying what they are. Test:
the defaults exist and the shown edge still derives from `bar.frame`/`bar.outline_width`
(`line`, 2 px → Regular), not from the transport.

### A3 · Low · `setters.apply` threw on a nil document — fixed

`setters.apply(nil, 1000)` indexed `nil` instead of setting nothing, although every other bad input
(a code outside the list, a negative code, `inf`, `NaN`) already returned `nil`. Guarded; test
`setters: a code applied to nothing sets nothing`.

### A4 · Low · Pure geometry threw on a dimension that had not arrived — fixed

The Overview's geometry assumed numbers and threw on `nil`: `atlas.grid`/`atlas.strip` on
`w`/`h`, `atlas.territories` on `ids` ("attempt to index a nil value" through `ipairs`). The scene's
facts are 0 until the first screen report, so this was a real "not yet" value, not a hypothetical.

Fixed with coercions in `shell/lib/atlas.luau`; test `overview geometry survives a fact that has not
arrived yet` (no screen → no cell/strip/territory, and a real screen still lays out 1920 wide).

### A5 · Medium · Three top documents disagreed with the tree — fixed

- `docs/TESTING.md` said **280 tests (2026-10-31)**; the gate reported 281 before this audit and 285
  after it. Its table also omitted four suites that exist on disk — `board.sh` (11 checks),
  `feed.sh`, `nexus.sh` (66 checks) and `wallpaper.sh` (58 checks). All four are now rows.
- `README.md` still said **"Status: Phase 5 in progress"** and described only the Ferrolume bar,
  while the shell gained the island kit, Control Nexus, the side notch, the music player, the
  wallpaper studio, the stash, the board, BMO and the ported Overview. The status line says what is
  there now and points at `STATUS.md`.
- `docs/DECISIONS.md` ended at **D112** while `STATUS.md` cites D113–D116. Entries added for all
  four (the Overview port, the Mission shape, spring edges, canvas edges).

### A6 · Medium · A visible button wired to nothing — fixed

`shell/mooi-notch.plm`'s Wallpapers panel has an **"Open the studio"** button that emits
`nt_studio`; no `on("nt_studio")` existed in any logic file, so pressing it did nothing, silently.
Found by the cross-file wiring scan. Fixed in `shell/mooi-notch.luau` with
`on("nt_studio", function() launch("mooi", { "wallpaper" }) end)` (`mooi` is already on that scene's
run allowlist).

`event nt_refresh ->` was the one declaration that provably promised nothing: no `emit nt_refresh`
in any source, no rule waiting for it, no handler. Removed.

### A7 · Low · No CI, and the launcher is still only syntax-checked here — open

Unchanged from the previous audit's F11: there is no `.github/`, `shellcheck` is not installed on
this machine (the gate says so and skips it), and `bin/mooi` is verified by `sh -n` plus reading.
The classes of defect `sh -n` cannot see (word splitting, unquoted expansions) are exactly the ones
that bit this launcher twice.

### A8 · Low · What a wiring check can and cannot claim — method note

A naive checker that scans one scene file against one logic file reports hundreds of mismatches,
all false. Three reasons, in order of how much they matter:

1. **Events are also passed by name as values.** The settings window calls
   `SChoice(…, set_value, 71000)`; the notch and the player call `Act(…, 5)`. A regex that looks for
   `emit NAME` therefore reports hundreds of "declared but never emitted" events that fire from
   inside a helper element. This is why a full dead-wiring scan is **not possible this way**, and why
   the only claims made here are the two names that were checked by hand: `nt_studio` (no handler
   anywhere) and `nt_refresh` (no emission and no rule at all).
2. Scenes `include` sources (`player/*.plm`, `ui/island.plm`, `theme/*.plm`, `bmo/*.plm`) — the
   contents must be resolved before counting.
3. One logic file serves one scene, but modules required from it register handlers for others
   (`environments.luau`, `stash.luau`, `notes.luau`, `signals.luau`), so comparisons must be global.

The scene half is enforced by the compiler regardless: `pleamar --check` refused an `emit ov_pan`
whose event was not declared, which is how this pass caught its own omission while adding D116.

| `config.validate` on its own defaults | **0 problems**; NaN, ±inf, `1e308`, negative and wrong-typed leaves each reported once, with their default named |
| `setters.apply` over codes 0–700 | 145 resolve, 556 set nothing, none throw or set the wrong path |
| Store readers (`notes`, `stash`, `board`, `wallpaper`, `player`, `atlas.identities`, `settingsfile`) | junk documents degrade quietly; no crash on any value their callers produce |
| `theme_sync` / `theme_watch` / `apps_sync` / `pace` / `settings_link` (read) | the previous audit's F4, F5 and F12 fixes are present in the tree |

**Correction, same day.** An earlier draft of this section recorded a lead: `notes.parse`,
`stash.parse`, `board.parse` and `wallpaper.recipe` "threw" when handed a list. That was the
**probe's** mistake, not the code's — those modules' readers are named `decode` (and the studio's
`recipe`), so the probe was calling a nil value. The real readers were then called 24 times with
junk shapes (a number, a string, a list, wrong-keyed objects) and `nil`: **0 throws**. No guard is
needed and no code changed for it.
