# mooi — full audit

Date: 2026-10-31 · HEAD `4886b30` (D112) · Pleamar 0.4.6 · language 0.4
Scope: the whole shell — `bin/mooi`, `shell/*.plm`, `shell/*.luau`, `shell/lib`, `shell/player`,
`shell/ui`, `shell/bmo`, the test suites, and the documents that describe them.

Method: read the code, ran `bin/mooi check` and the BMO suite, reproduced the failure modes that
can be reproduced without taking over the session, and cross-checked every claim the docs make
against the tree. Nothing here is based on a live run of the shell: starting mooi would have shown
it over the desktop (see "Not verified").

## Verdict

The code is in good shape for a project this size; the **verification pipeline is not**. 270 unit
tests pass and ten scenes compile, but `bin/mooi check` cannot report failure, the behavioural
suites are not part of it and are older than the surfaces they describe, and three top-level
documents are 38 decisions behind HEAD. The most likely way a real defect reaches the user is not
a logic error that the unit tests would catch — it is a regression in a scene, the launcher or the
settings file, which nothing automated currently guards.

## Findings

Severity: **High** = wrong behaviour a user can hit; **Medium** = wrong behaviour in a narrower
case, or evidence that cannot be trusted; **Low** = hygiene.

### F1 · High · `bin/mooi check` exits 0 even when tests fail — verified

`bin/mooi:923`:

```sh
cd "$root" && lua5.4 shell/bmo/test.lua | tail -1 && lua5.4 tests/unit/run.lua
```

The script has `set -u`, not `set -e`, and POSIX `sh` has no `pipefail`. `tests/unit/run.lua` does
`os.exit(failures == 0 and 0 or 1)`, but its status is never read: the `case` branch ends with the
`echo` of the Pleamar version, which sets the exit status to 0. Reproduced by running the exact
tail structure with a failing test: `FAIL something` printed, final `exit=0`.

`snapshot()` is safe (every check is `|| return 1`); only `check` has this hole. Any CI, wrapper or
habit that trusts `check`'s status is trusting nothing. **Fix:** `lua5.4 tests/unit/run.lua || exit
1` (and drop the `| tail -1` so a failure's text is visible), or capture the status explicitly.

### F2 · High · The behavioural suites are not gated and are stale — verified

`bin/mooi check` compiles scenes, parses logic and runs the pure unit tests. Every interaction
test lives in `tests/*.sh` and is run by hand. State of the record:

- `tests/scene.sh` is documented at **77 checks, 0 failed, 2026-10-20** — before the Ferrolume bar
  (D20–D24), the island kit (D97), the deck (D100–D108) and the music rims (D112).
- It still asserts the command membrane and the Mechanism bar (`tests/scene.sh:231–258`,
  `emit open_command`, "the membrane has left"), which D33 removed. It cannot be evidence for
  today's shell.
- `docs/TESTING.md` lists 10 scripts; the tree has 13. **`board.sh`, `feed.sh`, `nexus.sh` and
  `wallpaper.sh` are not in the index at all**, so their results are invisible to a reader.
- `docs/TESTING.md` still says **252 tests (2026-10-29)**; today's run says **270**.

So the only repeatable evidence for scene behaviour is roughly eleven days and ~40 decisions old,
and the suite that would catch a broken island is aimed at a bar that no longer exists. **Fix:**
fold the suites into `check` behind a `--quick` switch, refresh or retire `scene.sh`, and make
`TESTING.md`'s table generated from the scripts.

### F3 · Medium-High · `settings.json` has six writers with two different strategies — by inspection

Writers and their write sites: bar 15, settings window 5, player 4, wallpaper studio 4, Nexus 3,
notch 4. The good pattern exists — Nexus re-reads immediately before writing (`mooi-nexus.luau`,
`save_settings`: "read again: whatever changed elsewhere is kept"), and the player does the same
(`config.parse(read("settings.json"))`, then write). **The settings window does not**: it holds the
document loaded at start and `save()` writes that copy wholesale (`mooi-settings.luau:368`), with
four more unwrapped writes on the same in-memory table.

With the settings window open and the bar still clickable, a bar write (workspace labels, the wheel,
day/night) that lands before the settings window's next save is silently reverted. The bar's own
watch re-reads, so the bar is not the vulnerable side — the window is. **Fix:** make the window
follow Nexus's read-merge-write, or give settings one owner and have the programs send deltas.
Also worth pinning down: `files.write` atomicity is not documented in mooi, while
`bin/mooi identity` deliberately writes `*.tmp.$$` and renames. Decide and test one behaviour.

### F4 · Medium · The theme lock is held forever by the watcher — reproduced

`theme_sync` takes the lock with `exec 9>"$theme_lock"` + `flock -w 20 9` (`bin/mooi:145–146`) and
never closes fd 9. `theme_watch` calls `theme_sync` inside its own long-lived loop
(`bin/mooi:412`), so after its first recolour the watcher holds the exclusive lock for the rest of
the session. Reproduced in isolation: while a shell that had taken `flock` on a file slept, a second
`flock -n` on the same file reported **HELD**.

Effect: a manual `mooi theme-sync` (or any script calling it) while mooi runs waits 20 s and then
fails with "another sync is still running", although no sync is running. The watcher itself can
still sync (it re-`exec`s fd 9, releasing and retaking). **Fix:** close the fd after the critical
section (`flock -u 9` / `exec 9>&-`), or run each sync in a subshell.

### F5 · Medium · `pace()` depends on `bc` and splits on spaces — verified

`bin/mooi:577–578`:

```sh
for f in $(find "$1" -name '*.plm'); do
    awk -v f="$(echo "100 / $speed" | bc -l)" '
```

`bc` is not in the README's dependency list. With `bc` absent, `f=""` and the awk program
**exits 2 (division by zero)** — reproduced. Because the loop writes `> "$f.paced"` and only then
`&& mv`, the scene is left unpaced and a `*.plm.paced` file is left beside every scene, while
`mooi start` still reports success. Only reaches users who set `motion.speed` away from 100.
Separately, the unquoted `$(find …)` breaks on a path with spaces; the one `shellcheck disable`
in the file is on a different line and does not cover it. **Fix:** compute the factor in awk from
`100/speed`, and iterate with `find -print0` / `while IFS= read -r`.

### F6 · Medium · The settings window ignores write failures — by inspection

`grep` finds four **unwrapped** `sys.call("files.write", …)` in `mooi-settings.luau`; the player
wraps its equivalent and reports `COULD NOT SAVE THE SETTING`, the Nexus and BMO use `pcall`. A
failed write (read-only FS, full disk, a permission mishap) therefore throws inside the input
handler in the one program whose job is editing settings, with no message. **Fix:** one small
`save()` helper that pcalls, logs via `log()`, and sets a visible error fact.

### F7 · Medium · Performance claims predate half the shell — verified from docs

`docs/TESTING.md`'s idle figures (1.1 % CPU, 67 MB PSS) were taken **2026-10-20** with the
Ferrolume bar and "no island". Since then the shell gained the Nexus deck, the side notch, BMO,
the desk, the player, a 30 Hz visualiser feed and a wallpaper workspace — several of them always
on. There is no current measurement, and `STATUS.md` still quotes 195 tests.

Related, by inspection: the theme watcher wakes every ≤5 s and spends ~5 subprocesses per wake
(`readlink`, `stat`, three `jq`, `cksum`) even when nothing changed — about one process per second
forever, for a palette that changes once a wallpaper. Collapsing the three `jq` reads into one
`jq -c '[.theme.scheme,.theme.color_index,.theme.contrast,.theme.mode]'` and comparing the
wallpaper's `stat` before running anything would remove most of it.

### F8 · Medium · Three top documents disagree with HEAD — verified

- `STATUS.md`'s newest entry is **D74 (2026-10-24)**; `docs/DECISIONS.md` ends at **D112
  (2026-10-30)** — 38 decisions with no status line.
- `docs/TESTING.md`: 252 tests vs 270; four script files missing from the table.
- `README.md`: "Status: Phase 5 in progress", a bar description centred on the islands, and no
  mention of the deck/spine/notch that `TODO.md` marks as **built** (D100–D108).
- `TODO.md` still lists the music player and "Settings" as unfinished work while D112 is a player
  change; its "Next" block is accurate, its "Roadmap" block is not.

Depth is not the problem — `DECISIONS.md` is 290 kB of genuinely useful rationale. The problem is
that the entry point lies. **Fix:** make `STATUS.md` a dated one-screen summary that a script
regenerates from the last N decisions, or drop it in favour of HEAD's commit log; add the four
missing suites to `TESTING.md`.

### F9 · Low-Medium · Three independent IP-geolocation lookups — verified

`ipinfo.io` is called from the bar's weather module (`shell/bar.luau:253`), the weather island
(`shell/islands.luau:145`) and the Nexus/notch weather (`shell/mooi-nexus.luau:687`). Each is
documented for the bar but not for the other two; with a weather panel open that is up to three
requests disclosing the public IP. **Fix:** cache the lookup in one JSON file, as
`nexus-weather.json` already does, and have all three read it.

### F10 · Low-Medium · Scene monoliths and duplicated panels — verified

- `shell/mooi.plm` — 6,166 lines, 179 zones, 235 props; `mooi-settings.plm` 3,825;
  `mooi-nexus.plm` 2,065; `mooi.luau` 2,007. Total 19,193 lines of `.plm` and 20,266 of `.luau`.
- The project already has the right tool: `shell/player/*.plm` and `shell/ui/island.plm` are
  `include`d. The main bar does not use it, which is why 40 decisions all edit one file.
- Claude, GitHub, weather and music panels are implemented twice — once in the notch
  (`mooi-notch.plm`, 885 lines) and once in the Nexus (`mooi-nexus.plm`); both even write
  `nexus-weather.json`. The island kit is the natural shared home.

No dead code was found: every `shell/lib/*.luau` is required somewhere, every `.plm` is referenced.
That is unusually clean — the weight is in size and duplication, not in leftovers. **Fix:** move
the bar's islands (stash, notes, overview, shutter, deck) into `ui/` includes, one at a time, with
`bin/mooi check` after each; then let the notch's panels be the Nexus's.

### F11 · Low · No CI, no shellcheck, and `sh -n` is the only launcher check — verified

There is no `.github/`, `shellcheck` is not installed, and `check` validates the 945-line POSIX
launcher with `sh -n` alone — syntax, not quoting or word splitting. F5 is exactly the class of
defect `sh -n` cannot see. **Fix:** a CI job running `shellcheck bin/mooi tests/*.sh` plus the
(fixed) `check`, and the same two commands in a pre-commit hook.

### F12 · Low · Small hygiene items — by inspection

- `settings_link` renames a real folder to `*.old.$$` and never cleans up, so repeated runs
  accumulate directories in the Pleamar data folder.
- `apps_sync`'s `render()` leaves `*.mooi-tmp` behind when `sed` fails (the `&&` skips the `mv`).
- `mooi identity name` rejects only `\001` and `\177`; other C0 controls pass into a name that is
  drawn on the plate.
- `theme_sync` substitutes `$root` into TOML with `sed "s|@TPL@|…|"`; a repo path containing `&`
  or `|` mangles the config.
- `theme_watch` uses `flock` unconditionally, while `theme_sync` guards `command -v flock`.

## What is good — and should not be disturbed

- **Execution is argv-only.** Every `run()` in the logic takes a table; nothing is interpolated
  into a shell. The one place a shell is used (`bin/mooi`) is the launcher itself, and it uses
  `jq --arg`, `printf '%s'`, and temp+rename for the settings it edits.
- **Permission allowlists per scene** (`run:` in `mooi-nexus.plm`, `mooi-notch.plm`, `bmo.plm`,
  `mooi-board.plm`) with no `sh` in any of them.
- **`MOOI_SAFE` is honoured** at every write path checked, and the test harnesses rely on it.
- **Recovery is real, not aspirational:** a broken `settings.json` falls back to the last good
  copy; a theme that fails completeness/contrast is refused *whole*; the keeper stops after three
  quick deaths and says so on a notification; a refused system write is reported in the footer
  rather than faked.
- **Colour is enforced at the source** — semantic tokens, WCAG pair checks, a lightness-only lift
  for unreadable wallpapers (D24). Accessibility, motion reduction and battery-aware effects are
  first-class settings, not afterthoughts.
- **The pure/impure split is disciplined** — `lib/` holds the testable decisions and the logic
  files hold the wiring, which is why 270 unit tests can cover this much surface.
- **No dead libraries or scenes**, and `DECISIONS.md` records the reasoning (and the failures)
  behind nearly every choice.

## Not verified

These need the session or hardware, and were deliberately not run:

- Any live behaviour: the audit did not start or stop mooi, so no claim here covers what draws
  on screen, pointer/keyboard paths, or a real palette run.
- Idle cost, frame timing and memory for the current HEAD (F7).
- Multi-monitor, hotplug, fullscreen-over-bar, and a real second panel.
- The behavioural suites themselves (`scene.sh`, `nexus.sh`, …), which would take over the screen.
- A physical key press for binds, and input-to-visible latency.
