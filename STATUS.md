A move is not a choice, so **the Atlas stays open**, the tile says where the window went and the Spine pulses that workspace. Escape leaves the strip first, then closes the Atlas.
- **Previews you can promise off**: `p` flips `atlas.previews`. Off means the pictures are given back at once (`thumbnails.want()`) and none is matched into a tile while it holds — the promise is that nothing is captured, not that the tiles are blinded. It is a setting, so it survives a restart; a safe-mode run never writes the settings file, so the test harnesses cannot become your config.

The harness had missed it because `--say "key Escape"` injects keys into the scene; `tests/integration.sh` now drives real keys through the compositor (`wtype`). - **Phase 5, the theme pipeline (first slice)**: the brief's colour pipeline is built end to end — the fixed palette, a palette taken from the wallpaper with Matugen, the user's overrides, then completeness *and* contrast validation, then one atomic paint. The scene's semantic tokens are no longer literals: each is `rgb(r, g, b)` over three facts the logic sets (the only way Pleamar lets the logic hand over a colour), so a theme changes while the scene runs. A theme that does not pass is refused **whole** and the last good one stays on screen (the Spine's dot says so). `bin/mooi theme-sync` runs Matugen with **mooi's own config** (`theme/matugen.toml.in` + `theme/palette.json.hbs`), so it writes one file — the palette mooi reads (`palette.json`, declarative JSON of the Material roles) — and touches none of your theming; it passes the same `--source-color-index 0` your `matugen-theme.sh` does, so mooi and the rest of the desktop take their colours from the same source colour of the same wallpaper. `theme.source` stays `fixed` by default: wallpaper colours are opt-in, and a palette change can only ever touch colour facts (checked).
- **The Mechanism (the bar)**: the always-present rail, in four regions — **identity** (the mark → the bar's own menu: colours, labels, wheel, version and path), **workspace navigation** (the Atlas key, the wheel's door, then the scale of workspace positions at fixed pitch with the carriage riding it), **quick access** (search, the focused window) and **status**. Two rules hold it together: *geometry carries state, colour only confirms* (`accent.primary` is what is, `focus.ring` is what is pointed at), and *preview is not commit* — the wheel and the scale may show a workspace before the compositor goes there, while `↵` asks `workspaces.focus` at once and never waits for an animation. The surface is reserved for the rail, so what opens beside it floats over windows and takes no click (pleamar commits the input region from what is painted). Region D now carries the essentials, each reading the services and each **opening the system surface**, which owns the controls: network (signal bars, a solid link for a cable, a struck line when offline), Bluetooth (the rune, lit while the radio is on, a dot while it scans), brightness (a sun sized by the level) and volume (a speaker, struck while muted), then the battery key and the clock. A widget the machine cannot have is not drawn and the ones above it close the gap. Bluetooth is shown and never toggled: there is no documented write for it, so a switch that cannot be trusted to reflect would be worse than a state that can. Written up in docs/MECHANISM.md.

## Known gaps

- Multi-monitor untested (the LG was not connected). The Spine and current Workspace Atlas surface use one monitor.
- Islands cannot be dismissed by clicking elsewhere (a layer surface does not hear outside clicks). Esc, the Spine buttons, × and 30 s idle dismiss them.
- While an island holds the keyboard, Hyprland will not move the keyboard to a window: choosing a window (membrane ↵, its Focus satellite, an Atlas tile) closes the island first and dispatches once it has let go (~60 ms). If the focus does not happen, that island comes back with the reason.
- The Atlas board is rebuilt while it is open, so a window opening or closing moves the tiles under the selection (the selection is an index), and the move strip's subject follows it. A window that moves workspace while the strip is open is not re-read until the next report.
- The move picker is walked with ←→ or clicked: a scene key cannot be a digit (`key 1` is a load error), so a workspace cannot be typed at.
- Moving a window to the workspace it is already on is dispatched like any other move and reported as it comes back (it says it moved); it is not short-circuited.
- The theme's palette comes from Matugen's **dark** scheme (mooi is dark-first); a light scheme is not built, and neither is a named theme package or a Workshop UI for any of it. `theme.overrides` is validated but has no editor: it is a settings file today.
- The theme pipeline is proved from the palette file (a staged one and a real `theme-sync` run); the *automatic* wallpaper hook is yours to add — one line in your Matugen config or wallpaper picker (docs/SWITCHING.md, docs/DECISIONS.md D11) — because mooi does not edit your config.
- Global modes (Focus / Explore / …) are still only specified.
- Takeover has no notifications, tray or lock screen of its own yet (lock falls back to swaylock).

Found and fixed while verifying, all with the run above as the check:

1. **Nothing took the keyboard.** With each island declaring `keyboard: exclusive while open == <name>`, no key reached any island: typing landed in the window below and Escape did nothing, so the search looked broken and the islands looked stuck. The scene now declares it once on its first surface (`keyboard: exclusive while open != none`). Verified with real keys (`wtype`): typing reaches the field, Escape closes the membrane, the Atlas and the window island, arrows move their selections.
2. **The Atlas glitched on the way out.** Closing it emptied the tile model mid-animation (content vanished while the frame left) and flipped the hint text; the board is now left whole while it leaves and built from Hyprland's clients (every tile focusable) with pictures from `thumbnails`, opened with the last board so nothing flashes empty.
3. **Focusing a window silently failed.** While an island holds the keyboard, Hyprland ignores `hl.dsp.focus` for windows; `focus` now gives the slot up first, dispatches, and brings the island back with the failure if it did not happen. `tests/integration.sh` checks the focused window independently with `hyprctl`.
4. **The live harness could pass while the keyboard was dead.** `--say "key Escape"` bypasses the compositor, and the integration script piled leftover `mooi-probe` windows into the next sections (10 failures, mostly about the wrong window). It now closes strays before spawning, waits for closes to land, and drives real keys through `wtype` when it is installed.

Found and fixed while building the Mechanism, with the suite above as the check each time:

5. **A fact that did not exist.** `shell/mooi.luau` read `fact.atlas_max`; the fact is `ws_max`, so `sync_move_target()` raised `attempt to compare number with nil` on every Atlas selection change. `tests/scene.sh` and `tests/theme.sh` carried the same stale name.
6. **Region B sat on top of the workspace scale.** The wheel-door key (y 90–116) was captured by the `scale` list zone (from y 98) — Pleamar's own `describe` reported it as "covered by scale". `g.slots_y` 104 → 132 cleared it, and because everything below is relative one token moved the scale, Region C and the status stack with it.
7. **`pick` is 0-based and `if` is not.** Several labels read backwards (`Network — no connection` while online; the mark menu's Colours, labels and wheel), and the signal was shown as `strength * 100` even though `network.strength` is already 0–100. Ten labels corrected; the `pick`s that take a 0-based index were checked and left alone.
8. **The membrane's window-actions mode could not be reached.** Once `focus query` gave the field the writing cursor it kept eating Left/Right/Return, and the scene's `blur` does not take the cursor back, so the arrows and Enter of the window actions never reached their rules. The scene's single keyboard claim is now false for exactly that mode (`… and not (open == command and cmode == actions)`), which is what frees the field. Narrowing the condition on the island instead was measured and rejected: a second declarer silently replaces the scene-wide `while`, so a real Escape in the Atlas stopped reaching it.
9. **The Atlas's first open had no board.** `build_tiles()` only wrote the model while the Atlas was already up, so the very first open showed an empty model and the move strip had nothing to start from until a late `hyprctl` reply arrived — the board is now built once at startup and the strip is seeded from it the moment the Atlas opens, so a late reply cannot decide where it points.
10. **Three scene checks depended on where the mouse was resting.** The Atlas selects the tile under the pointer, so with the cursor over a tile the move strip correctly started on that workspace rather than the focused window's. The check now settles the selection and reads its expectation from where it actually landed.
